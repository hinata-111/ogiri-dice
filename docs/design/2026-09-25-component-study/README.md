# UI部品見本 01

## 実マップ移動検証版

最新のユーザー指定: コマは丸い頭・細い首・裾が広がる胴体を持つ青い人型ピン。顔や手足のない一般的なすごろくコマにする。単純な円柱と人物イラストは不採用。小さい番号を添える。下記の旅人素材は履歴。

原画を `tokyo-map-art-v3.png` に更新。西側・湾岸の街区を増やし、新宿・渋谷・六本木・品川・お台場などの表示座標を再配置。プレイヤー1に新規透過素材 `traveler-blue-v1.png` を使用。両方とも内蔵imagegenによる制作候補であり、地理的な正確さや完成品質を保証するものではない。

「見本を切替」から浅草方面・新宿・湾岸の開始位置、全体地図/現在地を選べる。開始位置の変更は検証用の試合再初期化。通常プレイのワープ機能ではない。

ブラウザ844×390で新宿とお台場の配置、透過コマ、隣接候補の視認性を確認。残る課題は4人分の素材と同一マス表示、経路が建物を横切る箇所の調整、画面外目的地の案内、実機タッチ検証。

`movement.html` は実際のマップ接続・マス種別と既存reducerを利用する。`node docs/design/2026-09-25-component-study/build-movement.mjs` で現行の純TSをブラウザ向けに型除去して生成する（Node 24で確認、外部依存なし）。生成先 `movement-modules/` と `movement.html` は手編集せず再生成する。

- 4点取得直後の状態を正規アクション列で作り、分岐j1から開始。
- 選択→決定で1マス移動。残り歩数、来た道の除外、到着、停止マスの判定は本番reducerを使用。
- 地図上の座標は原画に合わせた表示専用配置。元のmap.jsonや生成スクリプトは変更しない。
- 現在地周辺を明るく、選択経路を黄色に表示。カメラは現在地に追従。動きを減らす設定では移動アニメーションを抑制。
- ブラウザ844×390で浅草まで3歩を操作し、残り4→3→2→到着、所持金10→40万円を確認。純ロジック確認でも未接続先の拒否と到着賞金を確認。

未完了: コマの完成素材、原画と地名の地理的な整合、全経路の視認性、スマホ実機、回答/採点/次手番との連続プレイ。この版はゲーム全体の置換ではなく移動を検証する独立ページ。

**最新の画面構成は `landscape.html`。スマホ横持ち・全面マップを最優先とする。** `index.html` は部品カタログ、`scenes.html` は状態カタログであり、その縦方向のレイアウトを本番に採用しない。

`tokyo-map-art-v2.png` は新規生成した原画候補。内蔵imagegenを利用し、密集した街の初稿から建物密度と窓の細部を減らす修正を実施。文字、コマ、経路は原画に焼き込まない。原画のみを表示する切替も用意した。経路接続は未実装で、A/Bと番号コマはUI配置用の仮表示。

横持ち見本はブラウザ844×390でマップ全面表示と回答オーバーレイを目視確認。縦持ちでは横持ち案内を確認。スマホ実機のソフトキーボード、safe-area、タッチ操作は未検証。[生成プロンプト](art-prompts.md)も保存した。

## 画面構成 02

更新: 手番開始・採点待ち・代替採点・青/赤チャレンジ・到着・最終結果を追加し、合計10場面に拡張。下記の「3場面」は初回制作時の記録。現在の回答送信は採点待ちに進み、検証用ボタンで結果または代替採点を選ぶ。

青チャレンジ→回答入力→採点待ち→結果の流れをブラウザで確認。回答の保持と「4点→12万円」の切り替えを確認した。時計・得点・所持金は独立した固定例であり、ゲーム進行の正しさを検証したものではない。

素材の制作条件と残る画面は[素材制作・画面展開仕様案](../../superpowers/specs/2026-09-25-game-art-production-design.md)を参照。

`scenes.html` に移動・回答・結果の3場面を追加。上端の切替で表示を比較し、回答欄に入力した文章を発表画面へ反映できる。場面変更時は表示先へフォーカスを移す。

地図は新規の配置図であり、本番経路・東京の正確な地理・完成素材ではない。得点と時計は固定。移動確定は説明文の更新のみで、ゲーム進行を再現しない。ゲーム本体への接続前に、手番開始・採点待ち・到着・チャレンジ・最終結果の設計と正式マップ素材が必要。

ブラウザで候補Bと地図記号の連動、回答画面で目的地が消えること、入力した43文字が結果へ反映されることを確認。回答よりお題が目立たないよう結果画面のお題文字を縮小し、任意回答と矛盾しない汎用のコメント見本へ修正した。

`index.html` をブラウザで開く。外部通信・依存パッケージ不要の独立したデザイン試作。本番の描画技術選定やゲーム実装ではない。

## 比較できること

### 到着・チャレンジ画面の接続

到着を金色、賞金チャレンジを青、減額回避を赤で区別し、賞金・目標点を大きく表示する。到着から新目的地と次手番へ進み、チャレンジは回答→増減額の結果→次手番に接続した。本体の目的地選択・お題選択・定数を利用する。順位画面も実装したが、勝利までの通し検証は未完了。

844×390で浅草到着（10→40万円）→新目的地の六本木→はなこの手番を確認。青は1点・＋3万円の結果から次手番へ、赤は目標6点・不足点あたり3万円の説明を確認。赤の結果と最終順位の検証、マップ全域の位置調整は後続。メニューの「青マスの画面を試す」「赤マスの画面を試す」は合法なreducerアクションで検証用状態を作る。

以下の古い「チャレンジ・到着後の継続は未接続」という記録は、この更新で部分的に解消した。

### 共通造形の仕上げ・第一段階

`game-finish.css` に情報面、輪郭、操作の影、手番の青、決定の黄、地名札、目的地札を集約した。背景の彩度とコントラストを少し抑えて経路の輪郭を補強。進路ボタンはコマから86px以上離し、候補同士は56px以上空けて、対応マスへ案内線を表示する。

667×375のブラウザで4人同居・3分岐の通常/選択表示を確認し、コマとボタンの重なりを解消した。マップ全域の建物と経路の干渉、全場面の造形統一はまだ完了していない。完成条件は `docs/superpowers/specs/2026-09-25-ui-completion-checklist.md` を参照。

### 回答から移動まで（2026-09-25）

`movement.html` の「見本を切替 → 回答から移動まで試す」で開始する。手番案内から自分で「お題を見る」を押すと、本体の15秒ルールで回答を受け付ける。マップ右下の入力パネルから送信し、採点待ち・回答と点数の発表・点数分の移動へ接続する。

本体の `MockEvaluator` を使用するため得点はランダムで、回答の面白さを評価しない。外部AI通信は行わない。生成モジュールは `build-movement.mjs` で再生成する。時間切れは reducer の `TIME_UP` に従う。回答と採点をやり直す際は古い非同期結果を破棄する。IME変換中のEnterでは送信しない。

無回答のまま15秒経過したとき、1点・1マスの時間切れ結果になることもブラウザで確認済み。

844×390のブラウザで回答送信→採点待ち→回答文を保持した5点の結果→残り5マス表示を確認。入力フォーカスでマップ全体がスクロールする問題を修正した。実機ソフトウェアキーボードとGemini接続は未検証。チャレンジ・到着後の継続は依然として移動見本の範囲に留まる。

### 移動見本の4人表示（2026-09-25）

`movement.html` は青・赤・緑・紫の4人で開始。コマは承認された球形の頭と裾の広い胴体を持つ、顔や手足のないすごろくコマで統一し、番号を併記する。同じマスでは小さくして位置をずらし、手番のコマに白い縁光を付ける。

目的地表示を押すと浅草へ視点を移し、「現在地へ戻る」で復帰する。目的地の確認中は進路選択を隠す。残り歩数は左側のプレイヤー表示の下に配置する。

ブラウザの844×390表示で4人の配置、目的地確認と復帰、進路選択・決定後に青だけが移動して3人が留まること、歩数4→3を確認。JavaScript構文検査も通過。移動の検証用見本であり、回答・採点からの連続プレイや実機タッチ操作は今回の検証範囲外。

- 白い見出し帯／プレイヤー色の見出し帯。
- ワイド／390pxの部品配置、長い名前と回答。
- 進路候補の通常・キーボード注目・選択・無効・移動待機。
- 回答入力と発表時の文章サイズ。

候補は上下キーで注目、Enterまたはクリックで選択、独立した決定ボタンで確定する。無効候補も理由を確認できる。待機中は連打を抑止。ここでの選択と800ms待機はデモ用であり、ゲームのreducerには接続しない。

## 初期提案

白い面を基本とし、プレイヤー識別が必要な見出しだけ色帯を使う。黄色は選択と主操作、青はプレイヤー1とキーボード注目の輪郭に使用し、番号・カーソル・チェックを併用する。背景は分離確認用の単色。書体は端末依存の暫定値であり、素材原画・地図・コマは未制作。
