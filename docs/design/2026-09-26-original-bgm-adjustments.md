# 元のBGMをベースにした調整版

前回の新曲3案から方針を変更。ユーザーの「もともと使用していたBGMをベースに修正したい」に従い、現在の `app/src/audio/score.ts` と `engine.ts` を直接使用した試聴音源を作成した。

## 比較内容

| 版 | メロディー・コード | テンポ（マップ / タイトル） | 調整 |
| --- | --- | --- | --- |
| 元の曲 | 現行そのまま | 104 / 116 BPM | 現行の譜面・音色生成による比較用書き出し |
| A 音色を柔らかく | 現行そのまま。伴奏を含め全音の位置・長さを維持 | 104 / 116 BPM | 高域を抑え、立ち上がりを丸く。伴奏・打楽器を下げる |
| B もう少し穏やかに | メロディーの全音・拍位置・拍単位の長さとコード進行を維持 | 96 / 108 BPM | Aの音色に加え、ベース・和音・ブラシを半分に。キックを省く |

試作時点では元の曲の軽快さに近いAを推奨し、ゲームの音楽・効果音・設定値は変更せず試聴で方向を決める方針とした。採用後の反映内容は以下に記録する。

### 2026-09-27 採用結果

ユーザーが `board-soft.wav` を指定して採用を承認。マップ系BGM（通常・回答中・結果）の演奏にAの音色処理と伴奏バランスを適用した。16小節・104 BPM・全音の位置と長さは維持。タイトル曲と効果音には適用しない。

試聴版のRMS補正に一致する係数 `1.3069002740231315` を使用し、既存の音量設定・回答中の音量低減・結果時の音量低減・ファンファーレ時のダッキングを引き継ぐ。音色キャッシュを原曲用と採用版用に分け、効果音やタイトル曲との混同を防ぐ。

`engine.fidelity.test.ts` で実際に予定された16小節分の音・開始時刻・音量を合成し、採用WAVとの誤差が16bitの1段階以内であることを確認。17小節目の繰り返し境界、タイトル原曲との一致、効果音の音色分離、回答・結果中の音量も確認する。既存の停止・ミュート・タブ非表示のテストも継続する。これは最終コンプレッサー前の波形の自動検証であり、実機での聴感評価ではない。

## 作成と確認

- `app/scripts/render-original-bgm-variants.mjs` をNode 24で実行する。
- 既存の `musicBar()` を直接呼び、既存 `AudioEngine.sample()` を変更せずオフラインで実行する。新曲の作曲や既存譜面のコピーはしていない。
- 原曲の音色に対して2段のローパスと短いアタック処理を加える。メロディーの音域・楽器種別は変えない。
- 16小節と自然な余韻を22.05 kHz / 16bit / mono WAVとして出力。同じ場面内でRMSをそろえ、音量差だけに判断が引っ張られないようにしている。
- 全版でメロディーの一致を検査。Aは伴奏を含む全音の一致も検査。波形の有限値・ピーク・末尾の無音・WAVヘッダーを検査。譜面と音色生成ソースの変更がないこともハッシュで検査。
- マップのメロディー43音、タイトル62音は全版で一致。Aの全音数も現行と一致。最大ピークは全音源で-13 dBFS未満。
- 比較用の原曲もファイルへの書き出しであり、ブラウザの最終コンプレッサー・場面別音量調整・効果音を含むゲーム録音ではない。自然な末尾を持つ試聴版で、ループ完成版ではない。
- ブラウザでの連続再生確認は未実施。前回の試聴ページで内蔵ブラウザが終了したため、今回は直接再生できるWAVを主成果物とする。
