# ルール説明と手動での大喜利開始

ユーザー依頼: ゲーム開始直後に出題せず、ルールを説明し、各ターンを「大喜利をはじめる」で開始する。

- 既存の `turnStart` を開始待ちとして利用する。初回はルールのダイアログで回答時間、採点と移動、移動順、到着賞金、追加お題、勝利条件を説明する。「閉じる」またはEscapeでダイアログだけを閉じ、ゲーム進行・通信は発生させない。
- 2026-11-10追加依頼: ルールを閉じた後は盤面を操作できる開始待ちにする。右下に「第○ターン」、待機状況、「大喜利をはじめる」「遊び方」をまとめる。開始ボタンはルール表示中に操作できない。
- 「遊び方」は開始待ちに説明を再表示する。「みんなの状況」は開始待ちにも利用でき、順位・所持金・到着回数を確認できる。既存の「広く見る」「現在地へ戻る」「目的地」操作を利用し、マップボタンと開始ボタンが重ならないよう同じ操作エリアに置く。
- ルールの開閉は端末内の表示状態のみ。オンラインの権限・30秒の期限・reducerに変更は加えない。次ターンでは説明を自動表示せず、次の新規ゲームでは初回表示する。
- 2周目以降も開始ボタンを押すまで出題・回答時間の計測・CPUの回答を開始しない。全CPUのローカル設定も同じ操作とする。
- 通常の共通回答30秒、P1から固定順の移動、追加お題15秒は維持する。
- オンラインはホストが共通ラウンドを開始する。ホストが切断・退出中なら接続中の先頭参加者が代行する。全員切断中は次の開始待ちで停止し、復帰後に再開できる。
- サーバーで開始権限・接続・revision・phaseを検証し、サーバーがお題を抽選して既存reducerへ `BEGIN_ROUND` を渡す。クライアントからのお題は採用しない。
- 開始待ちの期限はnull。古い保存済みの開始待ち期限もtickで取り除き、過去のalarmの反復と自動出題を防ぐ。
- 回答中・移動中などの期限処理と追加チャレンジの進行は既存どおり。

検証: ルールの表示、開始前の長時間待機、ボタン後の30秒、次周の再待機、権限と代行、重複・古い操作、保存復元、WebSocket・alarm同期。既存変更を保持し、公開・コミットは行わない。
