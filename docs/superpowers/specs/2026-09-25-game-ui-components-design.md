# 大喜利ダイス 共通UI部品設計 v0.1

状態: 画面制作に先立つ設計案。描画エンジン非依存。2026-09-25。

> 最優先の修正: スマホ横持ち・全面マップを基本とする。以下のコンパクト寸法は部品の参考値であり、縦持ち画面の採用を意味しない。マップを背景に残し、必要なUIを重ねる。[横持ち原画見本](../../design/2026-09-25-component-study/landscape.html)を最新の構成案とする。

根拠: [公式ゲーム画面の観察と注釈](../../research/2026-09-25-console-ui-screen-analysis.md)。以下の数値は本作用の試作値であり、参考作品を実測した値ではない。

## 1. 設計の優先順位

「目立つカードを並べる」方式から、ゲームの主役に面積を渡し、必要な情報だけを周辺に置く方式へ変更する。

1. 部品の役割・情報順序・操作状態。
2. 大きさと画面占有率、長文時の伸縮。
3. 輪郭・面・文字・アクセントの共通ルール。
4. 部品見本での選択・確定・無効・待機の比較。
5. 場面に組み込み、素材と演出を決める。
6. 必要な描画方式を比較する。

## 2. 見た目の共通文法

### 面・輪郭

- 情報を読む面は明るい不透明面。盤面背景から分離する細い内縁と濃い外縁を持つ。
- 情報帯は横長で薄く、文章ウィンドウは広く、コマンドは行状にする。全部を同じ角丸カードにしない。
- 発表場面だけ大きい見出し・装飾を使い、通常操作に紙片や風景イラストを散らさない。
- 通常・選択・確定は面、輪郭、カーソル、文字の組み合わせで示す。

### 色の役割

| 役割 | 方針 |
|---|---|
| 本文 | 濃い中性色＋明るい面 |
| 現在の操作対象 | 共通の選択アクセント＋カーソル |
| プレイヤー識別 | 固有色＋番号＋名前。選択色と役割を分ける |
| 目的地 | 旗の形＋地名。色だけに依存しない |
| 青赤チャレンジ | 青＋獲得記号、赤＋警告記号、効果の文言 |
| 無効 | 彩度を落とし、理由を説明欄に出す |

正確な色値・書体・角丸の最終値は未選定。前案の値を自動採用しない。最初の部品見本では「ニュートラルな白いウィンドウ＋鮮明な選択色」と「プレイヤー色の見出し帯」を比較する。暗いガラス面や全要素への金色装飾は候補から外す。

### 大きさの基準

ワイドの部品見本は1280×720を基準にする。縦画面をこの比率から単純縮小しない。

| 項目 | ワイド試作値 | コンパクト試作値 |
|---|---|---|
| 安全余白 | 外周32 | 外周16＋端末の安全領域 |
| 本文文字 | 24 | 18 |
| 補助文字 | 18 | 16 |
| 主情報・お題 | 32 | 24 |
| スコア・移動数 | 64 | 48 |
| 操作行の高さ | 56以上 | 52以上 |
| 内余白 | 16〜24 | 12〜16 |

長文を縮小して収めず、折返し・高さ増加・縦スクロールを選ぶ。端末別の最小文字サイズとコントラストは、実表示で検証して決定する。

## 3. 状態モデル

| 状態 | 表現 | 操作 |
|---|---|---|
| 通常 | 通常面・本文 | 選択可能 |
| 注目中 | カーソル＋外輪郭 | キーボード焦点またはポインター位置。まだ確定しない |
| 選択済み | 塗り帯＋チェック＋対象説明 | 候補を保持。確認前なら変更可能 |
| 押下 | 縁・影を内側へ、サイズ不変 | 同じ入力を再受理しない |
| 処理中 | 処理名＋一定の待機表示 | 二重実行不可、偽の進捗率なし |
| 無効 | 彩度低下＋理由 | 実行不可。理由は読める |
| エラー | 記号＋理由＋次の操作 | 入力を保持し回復可能 |

フォーカスと選択を兼用しない。マウスが通過しただけで候補を確定しない。タッチは1回目で候補選択、決定操作で実行する。移動候補の選択解除・戻る操作は移動前に限り有効で、確定済みの一歩は取り消さない。

## 4. 部品カタログ

### C01 手番帯

- 構成: プレイヤー番号/識別画像 → 名前 → 所持金。情報のラベルと値を分ける。
- 外観: 横長の帯。全周を太枠のカードで囲まず、見出し側にプレイヤー色を使う。
- 寸法案: ワイド幅420、高さ72。縦画面は親幅に合わせる。
- 状態: 自分の手番／CPU／手番切替。切替中も前の名前を残さない。
- 長い名前は2行まで許容、金額を隠さない。本文と金額に同じ色を使わずとも、背景とのコントラストを確保する。
- 根拠: R02上部帯。検証: 4人、長い名前、0万円、100万円以上。

### C02 目的地表示

- 構成: 「目的地」＋地名、補助行に最短距離と到着賞金。
- 外観: 地名を最も強く表示。旗アイコンは装飾ではなく目的地識別に限定。
- 寸法案: ワイド幅320、高さ88。移動中は省スペース表示へ切替可能。
- 状態: 通常／新目的地／到着／到達経路なし。
- 今回の残り歩数をこの部品に混ぜない。距離と金額の数値には単位を必ず付ける。
- 検証: 画面外でも目的地が読める、長い地名が省略されない。

### C03 残り歩数カウンター

- 構成: 「あと」＋大きな数値＋「マス」。移動中のみ表示。
- 外観: 背景と分離した一つの面。数値の場所を固定し、減少時に周囲を揺らさない。
- 寸法案: 幅240、高さ80。残り0では無効な操作盤を残さず次の場面に移る。
- 根拠: R01右上。検証: 1〜6、コマに重ならない、目的地距離と誤認しない。

### C04 コマンドリスト・進路選択

- 構成: カーソル欄＋固有記号＋行ラベル。選択対象の効果は別のC05へ表示。
- 外観: 一体のウィンドウ内に縦の行を並べる。行全体の選択帯とカーソルを共用する。
- 寸法案: 幅280〜360、1行56以上。4行を超える場合は高さ増加か一覧内スクロール。
- 進路は地図のA/B/Cと一対一。地名のない隣接マスは「A 青マス」のように記号と種別で区別。
- 状態: 通常・注目・選択済み・処理中・無効。上下キーで注目を移し、Enterで候補選択、別の決定操作で一歩を確定。
- 根拠: R02選択行。検証: 同じ方向の2候補を区別、連打防止、ポインター離脱で確定しない。

### C05 説明・メッセージウィンドウ

- 構成: 任意の話者/対象ラベル → 本文 → 続行表示。主操作を複数並べない。
- 外観: 盤面下部の幅広い面。読む領域と操作領域を分ける。
- 寸法案: ワイド幅880以下、本文24、通常2〜3行。長文はスクロールで全文保持。
- 用途: 選択中マスの効果、チャレンジ説明、到着案内。単なる所持金一覧には使わない。
- 根拠: R02下段の説明欄。検証: 長文、金銭確定前後、赤チャレンジの不足額。

### C06 入力ガイド・決定操作

- 構成: 入力記号＋動詞。PCはEnter/Esc等、タッチは押せるラベルとして表示。
- 外観: 画面下端に簡潔に配置。操作対象のC04と同じ大きなカードを重複して作らない。
- 「戻る」は未確定の選択解除、「進む」は確定行動。場面に応じ「1マス進む」「回答を送る」と明記。
- SwitchのA/Bボタン図形は本作にゲームパッド対応がない限り表示しない。
- 根拠: R02下端。検証: 表示と実際の入力が一致、入力欄でEscがゲーム状態を変えない。

### C07 対戦サマリー

- 構成: 番号/識別画像、名前、順位、金額。詳細に到着回数。
- 外観: ワイドでは下端のコンパクトな帯。移動コマンドと同時に場所を奪う場合は詳細を畳む。
- 常設右サイドパネルは採用しない。回答中は非表示、手番案内では全員、結果では回答者を優先。
- 根拠: R04下端。検証: 4人・同順位・1人プレイ。スマホでは自分の情報＋一覧を開く操作。

### C08 お題・回答入力

- 構成: 文脈ラベル（通常/獲得/減額）→ お題 → 入力 → 文字数 → 送信。
- 外観: 大きな文章面。一般的な小さいWebフォームを中央に浮かべる形にはしない。
- お題と入力欄は画面の主役。背景絵やお題ごとの挿絵は必須にしない。
- 状態: 空入力／入力中／変換中／送信済み／時間切れ。IME変換確定と送信を分離。
- 検証: 100文字、複数行、ソフトウェアキーボード、残り時間を見失わない。
- 根拠区分: 本作固有の設計提案。今回の桃鉄・マリオパーティ静止画には回答入力画面の根拠はない。

### C09 タイマー

- 構成: 時計記号＋「あと」＋秒数。バーは補助で、単独にはしない。
- 寸法案: 数字40/32、数字の桁幅固定。お題の近くに配置。
- 状態: 通常／5秒以下／終了／採点中は非表示。警告は記号・文言を併用し点滅なし。
- 検証: 15→1→0、背景タブ復帰、読み上げが毎秒連発しない。

### C10 回答発表・採点

- 構成: 回答者 → 小さなお題 → 大きい回答文 → 点数＋効果 → 審査コメント。
- 外観: 回答を主役にした発表ウィンドウ。点数を先に読ませて回答が背景になる構成を避ける。
- 長い回答は文章領域を増やし、点数を別段に配置。点数の装飾で読字面積を削らない。
- 状態: 通常／青／赤／時間切れ／代替採点。通常は移動数、チャレンジは金額を主効果として表示。
- 検証: お題と回答の対応、全文読了待ち、再審査、二重確定なし。

### C11 地図マーカー

- 地名: 不透明な名札、背景と分離する輪郭。装飾より前に表示。
- コマ: 番号・固有色・シルエット。同一マスで複数人を識別可能にする。外観は未選定。
- 進路: 選べる道、注目している道、選択済みの道を輪郭と記号で区別。
- 画面外標識: 方向＋対象名。地図端に配置、押すと対象の場所を確認。
- 根拠: R01。検証: 4人重なり、全体表示、小画面、地名が道を隠さない。

## 5. 場面別の表示表

| 場面 | 常時表示する部品 | 畳む・隠すもの |
|---|---|---|
| 手番前 | C01、C02、C07、開始操作 | 残り歩数、入力 |
| 回答 | C01の簡略表示、C08、C09 | 盤面探索、全員の詳細 |
| 採点待ち | 回答者と送信済み回答、待機文言 | タイマー、再送信 |
| 採点結果 | C10、続行操作 | 進路、地図探索 |
| 移動 | C01簡略、C02簡略、C03、C04、C05、C06、C11 | 全員の詳細、常設サイドバー |
| 到着 | 地名・賞金のC05、本人の金額、続行 | 進路、残り歩数 |
| 最終結果 | 全員の順位、ベスト回答、再開 | 移動・回答操作 |

画面はこの表から組み立てる。部品をすべて一度に見せるボードを、そのままプレイ画面にしない。

## 6. 部品見本の制作要件

まずC04＋C05＋C06（選択・説明・確定）、C01＋C02＋C03（情報帯）、C08＋C09＋C10（文章・回答）の3組を比較する。

各見本には、部品ID、構成要素の番号、通常・注目・選択・無効・処理中、長文、小画面、採用理由を添える。単一のAI生成画像で状態や文字を決定しない。

見本の制作形式と本番描画方式は別。デザインツールのベクター、静止画、限定的な操作プロトタイプのいずれも許容する。本番のHTML/CSS・Canvas・WebGL・SVGの選定を、この文書では行わない。

## 7. 完了条件と残りの作業

本書で完了: 公式静止画の観察、部品の責務・構造・初期寸法、操作状態、表示フェーズ、前案から撤回する前提。

未完了: 部品の実際の描画見本、確定書体・色値・輪郭、素材原画、動き・音の比較、長文・実機検証、描画方式の選定。

この仕様だけで「デザイン完成」とはしない。上記3組の部品見本を作成し、視認性・識別性・操作意図を評価してから全画面へ展開する。
