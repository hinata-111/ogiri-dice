# 大喜利ダイス — 縦持ちゲームUI 現行仕様

更新日: 2026-09-26。状態: 今回のUI刷新は受入れ完了。画面構成の了承と、iPhoneの日本語入力・送信・キーボード表示の確認済み報告を受領。

## 1. 目的と優先関係

「大喜利で東京を巡る」を、スマートフォン縦持ちの全面マップで遊ぶ。現在地・進路・目的地を主役にし、回答時はお題と入力に集中できる専用表示に切り替え、結果はマップ上で見せる。東京の街並みを眺める楽しさと、次の操作が分かることを両立する。

この文書を画面・部品・素材の現行基準とする。同日作成のUI全面刷新案、共通UI部品v0.1、素材制作案、および独立HTML見本は検討履歴。食い違う場合は本書を優先する。ゲームルールは `app/src/game/rules.ts` と2026-07-08ゲーム仕様、状態遷移はreducerを正とする。

研究資料は[企業の公開資料と仕様書の書き方](../../research/2026-09-25-design-spec-writing-research.md)と[公式ゲーム画面の観察](../../research/2026-09-25-console-ui-screen-analysis.md)。企業資料からは用途・構成・状態・検証を分ける書式を採用し、ゲーム画面からは地図優先の面積配分と情報の階層を参考にした。作品固有のキャラクターや原画は流用しない。

## 2. 対象と画面構成

- 基本対象: スマートフォン縦持ち。393×852、375×667、320×568。横持ちとPCも継続対応。
- 縦画面の回転案内・操作禁止を廃止。全編を同じ向きで遊べる。
- 上部: 手番・所持金、目的地を2段で配置。残り歩数はその下。
- 中央: 現在地を追う全面マップ。進路候補は上下の操作領域を避ける。
- 下部: 地図・順位ボタン、その下に進路説明と決定。操作44px以上。
- 回答: 縦画面では開始時から可視領域全体に上から残り時間、お題、回答と送信を配置。キーボード開閉時も構図を維持し、お題は独立スクロール。
- 結果・最終順位: 縦積み。長文部分をスクロールし、結果の次へ進む操作は残す。
- 全体地図: 読める縮尺のスクロール表示と、全体を収める表示を切り替える。縮小時は地名を現在地・目的地に絞る。移動時は現在地へ戻る。
- 横画面の配置は従来の左右HUD・左右入力配置を基本に維持する。
## 3. 美術と描画の分担

| 層 | 採用内容 | 実装・素材 |
|---|---|---|
| 東京の原画 | 斜め見下ろしの街並み、公園、寺社、川、湾岸。UI文字を焼き込まない | `app/public/art/tokyo-board.png`。原画候補v3を使用 |
| 経路とマス | 原画上に合わせた経路。通常・青（＋）・赤（！）マス。選んだ区間は黄色 | `art-layout.ts` とSVG描画 |
| 地名 | 明るい不透明な札。目的地だけ旗と黄色 | HTML文字。複数人がいる地点は札を下げる |
| コマ | 丸い頭、細い首、裾が広がる胴体。顔・手足・帽子なし | CSS造形。青、赤、緑、紫と番号1〜4 |
| HUDと操作 | アイボリーの面、紺の輪郭、役割ごとのアクセント | React、HTML/CSS |

原画はimagegenで制作したもので、人間のデザイナー制作物とは扱わない。地理の縮尺を再現した地図ではない。プログラムの単純な線や図形で街の美術を代替しない一方、変化する経路・文字・コマは原画と分離する。現行表現に必要な2Dレイヤー、カメラ移動、入力をこの構成で実装している。旧Unityは変更しない。

経路の接続・色・マス数はゲームデータを使う。表示位置のみ `art-layout.ts` に分離し、17路線の曲がりを指定する。汐留〜お台場は吊り橋と島の外周を通る。全体地図と主要地点の視覚確認で、湾岸の橋、東京タワーとの重なり、2か所の立体交差を調整済み。実機での読み取りは最終確認待ち。

## 4. 共通スタイル

数値は現行実装のCSS px。コンソール作品の実測値ではない。

| 項目 | 基準 |
|---|---|
| 本文・輪郭 | 本文 `#183c59`、主輪郭 `#173f5b` |
| 読む面 | `#fffdf3`。風景上でも文章を透過させない |
| 手番・通常アクセント | 青 `#1679bb` |
| 主操作・目的地 | 黄 `#ffcf33` 系。全要素を黄色にしない |
| 書体 | Yu Gothic、Meiryo、sans-serif。太さ700、見出しは強調 |
| ボタン・入力 | 高さ44px以上。進路候補46px、候補間10px以上 |
| ウィンドウ | 外枠2px、上の役割帯5〜6px、角12〜14px、内余白12〜20px |
| 文字 | 縦のお題22px（キーボード時18px）、回答入力16px、結果点数64px。地名10〜15px、補助10〜13pxは実機可読性の確認対象 |
| 外周 | 左右16px、下12pxを基本としsafe-areaを考慮 |

文字を収めるための無制限な縮小はしない。長文は折り返し、ウィンドウ内スクロールで対処する。実際の小画面で文字と操作の両方が使えることを完了条件にする。

## 5. 操作状態

| 状態 | 表示 | 挙動 |
|---|---|---|
| 通常 | 明るい面、紺の枠と下影 | タップ可能 |
| フォーカス | 青または白＋青の外輪郭 | 選択確定とは区別 |
| 選択済み | 候補を黄色にし、経路も強調。下にマスの効果と距離 | 別候補へ変更可能 |
| 押下 | 影を浅くする | 大きさや周囲の配置は変えない |
| 無効 | 灰色の面、影なし | 未選択の決定は不可。説明は「マスを選んで決定」 |
| 処理中 | 採点中の文言と送信済み回答 | 二重送信しない。架空の進捗率を表示しない |
| 採点失敗 | 仮の点数と明示、継続と再採点 | 結果を本採点と偽らない |

進路は候補選択→決定の2段階。選択可能なマスはreducerの状態から導く。表示座標をずらした候補には実マスまで点線を引く。確定済みの移動は取り消さない。

## 6. 場面別の情報と操作

| 場面 | 最優先の情報 | 主操作・進行 |
|---|---|---|
| タイトル | タイトル、遊び始める入口 | はじめる。遊び方は3項目の開閉式 |
| 参加者設定 | 名前、人間/CPU、CPUの性格 | 1〜4人を設定して開始 |
| 手番開始 | 次の挑戦者の名前 | 人間は「お題を見る」まで待機。CPUは自動進行 |
| 回答 | お題、残り15秒、回答欄 | 送信。IME変換確定のEnterでは送信しない |
| 採点待ち | 送信した回答と採点中 | 結果を待つ |
| 採点結果 | 点数と効果を優先し、お題・回答・講評を続ける | 通常はNマス進む。チャレンジは金額を確定して次へ |
| 移動 | 現在地、残り歩数、目的地、選べる進路 | 候補選択→決定。地図/全員状況の確認も可能 |
| 青マス | 点数に応じた賞金 | 内容を読んでチャレンジ開始 |
| 赤マス | 目標点と不足点に応じた減額 | 内容を読んでチャレンジ開始 |
| 到着 | 到着した地名と30万円 | 人間は次の目的地へ進む。CPUは自動進行 |
| 全員状況 | 各人の順位、番号、名前、所持金、到着回数 | 閉じる。背後はinert、Escapeで閉じて入口へフォーカスを戻す |
| 最終順位 | 優勝者、4人分の順位と金額 | タイトルへ戻る。ベスト回答は初期展開し開閉可能 |

ゲーム定数はrules.tsから参照する。タイマーは人間がお題を開いてから開始する。採点結果の読み終わりを強制しない。ルールの変更と表示の変更を混同しない。

## 7. 演出と入力領域

- カメラ移動280ms、コマ移動260ms。点数発表まで600ms、点数の拡大表示240ms、到着ウィンドウの登場300ms。
- `prefers-reduced-motion` では移動・拡大・登場アニメーションを抑える。結果の内容は残す。
- visualViewportの高さをstageへ反映し、ソフトキーボード出現時の表示領域へ追従する。これは実装済みであり、実機で入力・送信まで確認済みという意味ではない。
- 到着・チャレンジ結果には変更前/変更後の所持金を表示する。目的地の変更時は4秒間「新しい目的地」と表示し、枠を500ms強調する。結果画面は回答/講評をスクロールし、点数/金額と下の操作を残す。縦画面は点数を上、横画面は左に配置する。667×375で100文字回答、賞金/減額、採点失敗を確認済み。減額は0万円の下限適用後の実際の増減を表示する。

### ソフトウェアキーボード表示中
回答パネルはvisualViewportの位置・幅・高さに追従する専用表示へ切り替える。縦画面は上にお題、下に回答入力と送信、最上部に残り秒数を配置。横画面はお題と入力を左右に配置。カテゴリと時間バーは省略するが、赤マスの目標点などの条件は表示する。入力16px、操作44px以上を維持。iPhone実機からの表示不良報告に対応した仕様で、修正後の実機受入れは未完了。


## レビュー対応実装（2026-09-26）

- 進路比較: 選択前から各候補のマス種別と目的地までの最短距離を提示。比較ボタンと地図の候補を同じ選択状態に接続。
- 全体地図: 900px以上の読める縮尺でスクロール。全体を収める切替では地名を現在地/目的地に絞り、同位置のコマを集約。現在地を明記。
- 設定: 色と番号で参加者をまとめ、操作種別・CPU性格を枠内に配置。自動フォーカスは開始ボタン。
- 回答: 縦画面は回答フェーズ開始時から専用表示。上部にお題、下部に入力・送信を配置し、キーボードの有無で構図を変えない。
- 採点: 点数と移動/金額を先に、元のお題と回答・講評を後に表示。ゲームロジックは変更しない。
- タイトル: 東京を巡る大喜利すごろくであることをコピーで提示。
- 到着/チャレンジ/最終順位: 到着の地名と賞金を拡大、赤青の構成と説明を整理、最終順位のベスト回答を初期展開。

Chrome393×852で設定→回答→採点→比較からの移動、地図の拡大/全体表示を確認。393×390への縮小時にもお題と入力/送信を表示。375×667で到着・順位・長文結果を確認。iPhone実機は再確認待ち。原画自体の新規制作や再戦ルール変更はこの修正に含めない。

## ユーザー確認

修正版の確認報告と構成への了承（「確認した」「ok」）を受領。この構成を今後の基準とする。確認端末・日本語IME・全場面の個別試験結果は追加報告されていないため、了承をそれらの試験合格とは読み替えない。
