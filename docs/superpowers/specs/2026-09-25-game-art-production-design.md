## アートの方向

推奨案は「立体感のある卓上の東京」。街を小さな模型として見せ、読みやすい不透明なウィンドウを重ねる。ゲーム画面の主役は現在地と次に進む経路。地図の絵は東京らしさと目的地の記憶を支える。

比較案は平面の絵地図。経路の読みやすさと制作量では有利だが、都市を巡る立体的な楽しさは弱い。最初に同じ一街区を両案で制作し、コマ・経路・地名が読み取れるか比較する。現状のCSS仮図はどちらの完成見本にも数えない。

桃鉄やマリオパーティから参照するのは情報の配置・選択状態の伝え方。キャラクター、乗り物、枠、アイコンの原画は新規に制作する。

## 共通の描画基準

- カメラ案: 固定の斜め見下ろし。経路判断時に回転せず、現在地と分岐を同時に見せる。
- 光: 左上からの柔らかい一方向光。素材ごとに光源を変えない。
- 形: 建物は大きな輪郭と2〜3段階の明暗で表す。細かい窓や看板を増やさない。
- 層: 地形 → 装飾 → 経路 → マス → コマ → 名札 → HUD。建物で道を隠す場合は建物側を退避または簡略化。
- 色: 草地と街区は低めの彩度。青赤マス、現在のプレイヤー、目的地が先に見えるようにする。
- 文字: 原画に焼き込まない。地名、番号、金額、ボタン文言は独立した文字層。
- 背景の動き: 操作中は静かに保つ。発表と到着で演出を集中させる。

## 制作順と受入れ条件

1. 一街区のアート比較: 同じ地形・経路で平面案と模型案を作る。白い仮背景だけで判断せず、HUDを重ねて比較。
2. コマ4種: 実表示サイズと半分のサイズで番号とシルエットを比較。4人同一マスで重ならない配置も作る。
3. マスと経路: 分岐、接近する道、建物の裏を通る道を確認。装飾の道路を進路と誤認しない。
4. 地名と目的地: 最長地名、小画面、全体地図、画面外標識で検証。縮小して文字を潰さない。
5. 到着演出: 確定済みの賞金と所持金を一度だけ表示。スキップや動きの抑制でも結果を読める。

一枚の雰囲気画像だけで素材を確定しない。各素材は透過背景、通常サイズ、拡大図、盤面上の使用例を揃える。画像生成を使う場合も、文字と操作状態は独立して制作する。

## 描画方式の判断に必要な実証

2D素材の移動と拡大で十分なら2D描画を検討する。立体物の遮蔽・カメラ・光を動的に変える必要が残るなら3D描画を検討する。日本語入力はIMEとソフトウェアキーボードを実機で検証する。

候補を決める前に一街区の完成素材と4人のコマを置いた検証場面を用意し、文字の鮮明さ・低性能端末の操作応答・素材容量・小画面の読みやすさを比較する。現行見本がHTMLであることは採用理由にしない。
