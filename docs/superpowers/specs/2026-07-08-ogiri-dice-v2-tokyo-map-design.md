## 元仕様からの忠実再現ポイント

1. **マップ**: `map.md` の東京お笑い劇場・テレビ局ネットワーク(分岐グラフ)
2. **回答制限時間**: 15秒(`UI_UX_PLAN.md`。ユーザー確認済み)
3. **移動**: スコア分のマスを**矢実キー/方向ボタンで手動移動**(`UI_UX_PLAN.md`「矢印キーで移動」)
4. **青/赤マス**: 金額の即時増減ではなく**追加お題チャレンジ**(`UI_UX_PLAN.md`)
5. **勝利条件**: 合計100万円(`README.md`「合計100万円を目指し、目的地の劇場を巡る」)
6. **状態演出**: 待機=落ち着いた色 / 評価中=黄・オレンジ集中色 / 結果=短く光る(`SCENE_STRUCTURE.md` Background Lights)
7. **通常ターンの回答は移動力のみ**(金は青/赤チャレンジと目的地到着で稼ぐ。ユーザー確認済み)

### 意図的な逸脱(技術的必然)

- Geminiモデル: 元仕様の gemini-1.5-pro/flash は廃止済み → gemini-2.5-flash 単一+リトライ(fallbackパターンの精神は維持)
- Unity/ScriptableObject 関連の記述は Web 技術に読み替え(v1設計書どおり)

## ゲームルール v2

### コアループ(1ターン)

1. 手番プレイヤーにお題表示 → **15秒以内**に回答入力
2. Gemini採点: スコア1〜6 + ツッコミ(時間切れ=スコア1「時間切れ！」)
3. スコア発表演出 → **スコア=歩数**として手動移動開始
4. 1歩ずつ方向ボタン(PC: 矢印キー可)で隣接マスへ移動。来た道へは戻れない(行き止まりを除く)
5. **目的地を通過したら即到着**(残り歩数切り捨て、桃鉄方式)
6. 止まったマスの効果(青/赤チャレンジ等)を解決 → 次のプレイヤーへ

### マス種別と効果

- **⬜ 通常**: 効果なし
- **🟦 青マス(チャンス)**: 追加お題が出題される。回答スコア×3万円を**獲得**
- **🟥 赤マス(ピンチ)**: 追加お題+目標値T(1〜4のランダム)が提示される。回答スコアがT未満なら (T−スコア)×3万円を**失う**。T以上ならセーフ(増減なし)
- **🏢/📺/🚉 拠点(劇場・テレビ局・駅)**: 通過・停止可能なノード。効果なし(目的地のときのみ到着処理)
- チャレンジの回答も15秒制限・時間切れ=スコア1。チャレンジでは移動しない(金銭のみ)

### 目的地システム(桃鉄式)

- 常に共通の目的地が1つ(🏢劇場/📺テレビ局からランダム抽選、全員の現在地は除外)
- マップ上に旗マーカー+HUDに「目的地: ○○」表示
- 最初に到着したプレイヤーに**到着ボーナス30万円** → 次の目的地を即抽選
- 到着はメイン移動中の通過で成立(チャレンジ中は無関係)

### 所持金と勝敗

- 初期所持金: 10万円。下限0円
- **勝利: ターン終了時に所持金100万円以上で即優勝**
- 保険: 全員合計30周(1人30ターン)経過で終了、所持金最多が優勝(引き分けは到着回数)
- リザルトで順位・所持金・到着回数・ベスト回答集(スコア5以上)を表示

### CPU

- 回答生成は v1 と同じ(Gemini、性格 safe/bold、失敗時定型回答)
- 移動は目的地への最短経路(BFS)を自動で1歩ずつ進む(人間と同じ見た目)
- チャレンジも人間と同じフローで自動回答

### データ形式

```ts
interface MapNode {
  id: string;
  name: string;          // 表示名(中間マスは"")
  kind: "theater" | "tv" | "station" | "stop"; // stopは中間マス
  cell: "normal" | "blue" | "red";             // マス効果(拠点はnormal)
  x: number; y: number;  // アイソメ配置座標
  neighbors: string[];   // 隣接ノードid(双方向整合必須)
}
```

`data/map.json` に全ノードを格納。ロード時に双方向整合性を検証する。

## 状態遷移 v2

```
Title → Setup → [ターンループ]
  TurnStart(カメラ手番コマへ)
  → AwaitingAnswer(15秒、メインお題)
  → Evaluating → ShowingResult(スコア発表)
  → Moving(残り歩数N、手動/CPU自動で1歩ずつ。STEP_TO(nodeId)で減算)
     ├─ 目的地通過 → Arrival(到着演出+30万+次目的地抽選) → TurnEnd
     └─ 歩数0で停止 → 停止マス判定
        ├─ 青/赤 → ChallengeIntro(目標値表示) → AwaitingAnswer(チャレンジ)
        │   → Evaluating → ShowingResult(金銭増減表示) → TurnEnd
        └─ 通常 → TurnEnd
  TurnEnd: 100万以上→GameResult / 30周経過→GameResult / それ以外→次プレイヤーTurnStart
```

- reducer は v1 同様、唯一の状態変更点・不正遷移は無視
- `AwaitingAnswer`/`Evaluating`/`ShowingResult` はメインとチャレンジで共用し、`context: "main" | "challenge"` で区別
- 背景演出: フェーズに応じて body/背景レイヤーの色クラスを切替(待機=紺の落ち着き / 評価中=黄橙パルス / 結果=フラッシュ)

## 描画: 2.5Dアイソメトリック(ユーザー承認済み)

- SVG継続。マップ座標をアイソメ風に配置し、拠点は簡易アイソメボックス(建物風)+名称ラベル、路線は道風の太線、中間マスは色付きタイル
- カメラは手番コマ追従(v1のカメラ機構を流用)
- 移動可能方向は矢印ボタンをコマ周囲にオーバーレイ表示(スマホタップ対応)。PCでは矢印キーでも操作可
- 目的地に旗+バウンドアニメ
