# Map Space and Travel Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 同じ東京マップのマス間を広げ、通常表示と「広く見る」の差と移動距離を明確にする。

**Architecture:** 配置データとゲーム状態を変更せず、カメラの描画幅で盤面を広げる。隣接候補は表示だけのカメラ入力として渡し、マスの図形サイズは描画倍率と分離する。

**Tech Stack:** React 19 / TypeScript / Vitest / CSS transitions。

---

1. `TokyoBoard.test.tsx` へ通常/広域の倍率差と最短隣接距離100px以上（標準画角）、スマホ候補表示のテストを追加して失敗を確認。旧1.05倍固定の期待は新しい表示要件へ更新する。
2. `ui/constants.ts` に通常倍率・最低描画幅・マス基準幅を集約し、移動表示を520msに調整する。
3. `useMapCamera.ts` の通常倍率を広げ、任意の隣接候補を見渡せるよう必要時だけ追従倍率と位置を調整する。既存のcover下限・ドラッグ・ピンチ・復帰・小数丸めの保護を維持する。
4. `TokyoBoard.tsx` から表示用の隣接候補を渡し、マス/強調枠/立体交差マスクの見た目のサイズを補正する。
5. `tokyo-board.css` の道路幅を一定にし、カメラとコマの移動表示時間を揃える。縮小・手動見回しとreduced-motionの挙動を維持する。
6. 関連テスト→全テスト・build・lint。ブラウザの盤面プレビューでPC/スマホの通常・広域・1歩移動を確認し、検証対象と結果を追記する。

追記: レビューで見つかったスマホ・六本木の長い区間は、cover下限を維持したまま方向案内から候補へ視点を移す。移動は発行しない回帰テストを先行し、見回し時の案内と操作ボタンの重なりも解消する。

## 実施・検証結果

- 通常/広域の差がほぼなく、最短間隔が約55pxしかないことを失敗するテストで確認後、通常倍率2.2倍・小画面の最低幅2600pxへ変更。標準画角では最短間隔100px以上を確認。
- 背景画像・生成map.json・art-layout.tsのSHA-256は前回公開版と一致。全36マス・38接続・経路・色・目的地ルールを維持した。
- マス/強調枠/交差マスクは倍率で図形を補正。コマとクリック領域は従来サイズ。道路幅を一定にし、コマとカメラを520msで表示する。CPUの歩行間隔もこの表示時間から計算される。
- 追従では合法な隣接候補を含めて必要時に引く。レビューの全マス・全隣接元調査で再描画ループはなし。cover下限でも入りきらない長い区間は、矢印ボタンで候補に寄ってから実マスを選べるようにした。
- app全159テスト成功後、候補への寄り方と案内の配置を微調整し、関連30テスト・build・lintを再実行して成功。
- 実ブラウザの1280px幅と390×844で通常/広域の違い、1歩移動で残り6→5、スマホ六本木の画面外候補→候補へのズーム→実マス選択で残り6→5を確認。広域表示の案内と操作の重なりも解消。
- reducer・Worker・protocol・ゲーム定数に変更なし。カメラと表示用定数のみを変更。
