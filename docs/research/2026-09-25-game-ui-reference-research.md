# 大喜利ダイス：参考にするゲームデザインの調査

調査日: 2026-09-25 / 状態: 参考候補。採用未決定。

## 調査方法

公式サイトの説明・掲載画像を調査。桃鉄2のマップ画像とマリオパーティのボード画像はブラウザで目視した。ゲーム本体を操作した評価ではなく、アニメーションの実測や操作レスポンスの評価は含まない。

「確認できたこと」と「大喜利ダイスへの提案」を分ける。企業のデザインシステムからは仕様の書き方、ゲームからは体験と画面表現を学ぶ。

## A. 主参照：桃太郎電鉄2 / KONAMI

公式: https://www.konami.com/games/momotetsu/2/play.php

目視画像: https://img.konami.com/games/momotetsu/2/s/img/play/mass_ss.jpg

確認できたこと:
- マップ画像は、白い地名プレートと太い黒文字、経路として判別しやすい線路、色の異なるマスを使用している。
- 建物や名産物が密集していても、地名と経路は背景から分離されている。
- 公式説明では目的地の決定、移動、到着報酬の流れを段階別に示している。

採用候補:
- 地図上の地名・進路・現在地を装飾より優先する階層。
- 目的地、到着する価値、移動可能量を別情報として表示する。
- 東京の劇場やテレビ局の個性を、地名とランドマークで伝える。

そのまま移さない部分:
- 多数の物件・カードを前提にしたメニュー構成。
- 家庭用ゲームの横長画面をそのまま縮小すること。
- 桃鉄の青赤マスは直接金銭増減。大喜利ダイスは追加お題チャレンジなので、色だけで同じ効果を想起させず説明を付ける。

観察の限界: 今回目視した画像はマップ主体であり、常時HUDや各ダイアログの細かな仕様の根拠にはしない。

## B. 補助参照：スーパー マリオパーティ ジャンボリー / 任天堂

今回の参照版: Nintendo Switch 2 Edition ＋ ジャンボリーTV。

公式: https://www.nintendo.com/jp/games/switch2/a7hla/sugoroku/index.html

目視画像: https://www.nintendo.com/jp/games/switch2/a7hla/assets/img/sugoroku/poster_about_1.webp

確認できたこと:
- ボード画像は大きなランドマーク、連続する道、色付きのマスで構成されている。
- 公式説明では勝利やスター獲得に応じて王冠やフレームが変わる演出が紹介されている。

採用候補:
- 東京の各エリアに覚えやすい目印を作る。
- 現在の手番・獲得・優勝を、枠や形状の変化でも知らせる。
- 常時UIの装飾量を抑え、成果が出た瞬間に表情を付ける。

そのまま移さない部分:
- 大規模な3Dステージ制作やカメラ連携。
- 同作のスター・コインという複数資源を、本作の金額表示に追加すること。

観察の限界: ボード画像はUI表示の少ない紹介画像。プレイヤー情報枠の寸法・配置・操作仕様まで確認済みとは扱わない。

## C. 大喜利部分の参照：Quiplash 3 / Jackbox Games

公式: https://www.jackboxgames.com/games/the-jackbox-party-pack-7/quiplash-3

確認できたこと: お題への回答を競わせ、他プレイヤーや観客が好みの回答を選ぶ構成。公式ページでは回答後の対決と、複数回答を求める最終ラウンドを説明している。

採用候補:
- 自分が入力する場面と、全員で回答を読む場面を明確に分ける。
- 結果では点数だけでなく「お題・誰の回答か・回答文」が理解できる構成にする。
- 審査コメントが回答そのものより目立ちすぎない階層を検討する。

そのまま移さない部分: 投票や別端末入力の方式。Gemini採点・1台での遊び方とは前提が異なる。

観察の限界: 今回は公式テキストで体験構成を確認。書体・配色・入力画面の詳細を採用する根拠にはしない。

## D. 導入体験の補助候補：あつまれ どうぶつの森 / 任天堂

参照: https://www.nintendo.com/jp/ichikara/acbaa/index.html

資料の性質: 任天堂サイト掲載、GameWith編集部による紹介記事。開発者の設計説明ではない。

確認できたこと: 案内役の説明と、手続き・到着・生活準備という段階的な導入を紹介している。

採用候補: ルール全文を最初に読ませる代わりに、初回の回答・移動・チャレンジで、その時必要な説明を案内役が伝える。

注意点: ゆっくりした導入テンポは15秒回答ゲームとは相性が異なる。ビジュアルの主参照にはしない。

## 推奨する使い分け（本調査からの提案）

| 設計対象 | 主な参照 | 本作で満たしたいこと |
|---|---|---|
| 地図・地名・進路 | 桃鉄2 | 次にどこへ進むか判断できる |
| 手番・獲得・勝利の見せ方 | マリオパーティ | 状況変化が見て分かる |
| お題・回答・結果の構成 | Quiplash 3 | 回答を読む楽しさを守る |
| 初回説明 | どうぶつの森の導入紹介 | 必要な場面でルールを理解できる |

複数作品の色や書体を混ぜるのではなく、各作品から参照する役割を限定する。見た目の方向は次の比較対象として検討する。

1. 旅のボードゲーム中心：地図を主役にする。移動と目的地が分かりやすい一方、回答の読ませ方には専用設計が必要。
2. お笑い番組中心：お題と回答を主役にする。大喜利らしさが出る一方、地図の存在感が弱くなりやすい。
3. 場面別に主役を切り替える：移動は地図、回答はお題、結果は回答を主役にする。切替規則と共通UIの設計が必要。

推奨は3。ただし共通する書体・色の役割・ウィンドウ形状を決め、一つの作品として統一する。これは未承認の方向案である。

## 次のデザイン検討で比較する画面

- 4人参加の移動画面：手番、所持金、目的地、分岐が同時に理解できるか。
- スマートフォンの回答画面：お題、残り秒数、入力、送信がキーボード表示時にも使えるか。
- 長い回答の採点画面：回答文を読んでから点数とコメントを理解できるか。
- 青赤チャレンジ：通常のお題と違う目的を、色以外でも理解できるか。

今回未検証: 各ゲーム本体での操作、演出の時間計測、モバイルへの転用検証。参考画像はリンクで保持し、プロジェクトのゲームアセットとして取り込まない。
